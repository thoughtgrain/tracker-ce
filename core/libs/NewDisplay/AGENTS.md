# core/libs/NewDisplay: FT812 display and controls

This adds to the root [AGENTS.md](../../../AGENTS.md); it doesn't replace it.

- **Controls build their display lists in the MCU now.** While a control's `update()` stages run, the `API_*` calls append words to a capture buffer (`core/libs/FT812/DisplayList.h`) instead of driving the chip's coprocessor. `cDisplay::buildControl` stores the result in an arena in external RAM; `cDisplay::composeFrame` puts the frame together and only the words that differ from the chip's back list are sent. A frame identical to the one on screen isn't sent at all, and `synchronizeRefresh()` no longer does anything.
- **The frame budget still drops controls silently.** `cDisplay::composeFrame` walks the visible controls in reverse creation order and leaves out any whose list would push the frame past 8,172 bytes (`kFrameControlBytes`). Smaller controls after it can still fit, so what disappears depends on sizes. A list that doesn't fit its build buffer or the arena is discarded whole. Both cases only increment `displayList::overflows`; nothing is logged. `cDisplay::composedFrame` returns the last frame's words for measuring.
- **A coprocessor command with no MCU expansion is dropped from the list.** The capture in `FT812.cpp` and `DisplayList.cpp` expands the commands the controls use today (text, numbers, gradients, bitmap set-up, the 270-degree rotation). Any other coprocessor command made during a capture is counted in `displayList::droppedCommands` and not drawn. Add its expansion before using it in a control.
- **Control setters can be reached from the interrupt.** `cDisplay::setControlText` and friends are called from MIDI handlers today (see `core/source/AGENTS.md`). They only touch the control's state, but they race with the main loop building that control's list. Don't add more interrupt-side callers; set a flag and refresh from the screen's `update()`.
- **Graphics memory (RAM_G) is still laid out by hand.** Fonts start at 0, the bitmaps in `bitmaps` (`display.cpp`) sit at the fixed addresses written in that table, the image viewer decodes at `ImageViewerJpegAddress` and the project cover at `imgRamAddress`. Work out the addresses before adding a bitmap or decoding somewhere new.
- **Style bits are a shared bit field.** The `controlStyle*` values in `displayStructs.h` use bits 0–29, so only 30 and 31 are left. Never reuse a bit.
