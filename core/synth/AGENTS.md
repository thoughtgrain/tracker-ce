# core/synth: synth engines

This adds to the root [AGENTS.md](../../AGENTS.md); it doesn't replace it.

- **Two kinds of engine live here.**
  - **SDK engines** (`core/synth/engines/`) run inside Polyend's precompiled library, so they're Tracker+ and Mini only. Everything for them is `FEATURE_SYNTH` only: wrap new files in `#ifdef FEATURE_SYNTH` like `registry.cpp` does. Recipe: `synth-engine`.
  - **Open engines** (`core/synth/open/`) run on all three devices, the Original included. They have no `FEATURE_SYNTH` guard and must never include `PolySynth` headers, because the Original build has neither. TORO is CE's own; the rest are ported from OpenTracker (Apache-2.0, see `NOTICE.md`). Only the engines come from there, and the host around them is CE's own ([`docs/design/open-synth-host.md`](../../docs/design/open-synth-host.md)). Recipe: `open-synth-engine`.
- **Voice code runs in the audio interrupt, for both kinds.** Open engines are called from the audio path directly. For SDK engines, the PolySynth library is precompiled. Inside `Synth::renderAudioBuffer` (called from `PolySynth::update` every block), it calls your voice's `renderVoiceAudio()`, `onNoteOn()`, `onNoteOff()` and the other SDK overrides. Write them like any audio `update()`: no heap, no SD, no `double`, no UI.
- **Engine IDs are stored in projects.** Append, never renumber: `OpenEngineId` for open engines, and for SDK engines add new engines to the end of `InstrumentTypeId` (`synth/include/PolySynth/config.h`) and never renumber. To add one, follow the `synth-engine` recipe ([`docs/recipes/synth-engine.md`](../../docs/recipes/synth-engine.md)); the background is in the [developer guide §4](../../docs/developer_guide.md#4-synthesizer-engine-architecture--guidelines-tracker--tracker-mini) and [`docs/custom_synth_sdk.md`](../../docs/custom_synth_sdk.md).
- **Inactive engines should cost nearly no RAM.** Every registered engine exists from boot. Open engines are stateless singletons with fixed-size voice and slot state. SDK voices should derive from `CustomSynthVoice` (static parameter tables). Put big tables in flash (`constexpr`) or `EXTERNAL_RAM`.
- **Port open engines with renames only.** The diff against OpenTracker is the proof the DSP is unchanged, so keep it small, and record every change in the file header.
- **On Tracker+ and Mini, open engines are hosted through the SDK.** `core/synth/engines/OpenEngineVoice.h` presents any open engine to Polyend's library as an SDK voice. An engine's SDK file (TORO's is `ToroSynthVoice.cpp`) then holds only metadata: names, formatters, MIDI CCs, sections, macros, and handlers that call `setParam`. The sound and note behaviour live once, in the open engine.
- **TORO's sound is pinned.** `tests/toro/sdk_regression_test.cpp` checks TORO on Tracker+ and Mini against goldens recorded from the original SDK voice, so existing projects keep sounding the same. Change TORO's sound only on purpose, and say so in the PR when you re-record.
